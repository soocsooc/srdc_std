# STEP8 迷路ロジックのシミュレーター

`srdc_8_micromouse` の迷路ロジックを、実機の `.cpp` を書き換えずに PC の g++ でコンパイルし、ランダムな迷路で探索走行と最短走行を確かめるツールです。対象は `map_manager.cpp`、`search.cpp`、`search_dynamic.cpp`、`fast.cpp`、`misc.cpp` で、`MISC::modeExec()` も実機のものを使います。

走る様子や歩数マップを画面で見たいときは、同じ迷路ロジックをシミュレーター mms の上で動かす [tools/step8_mms](../step8_mms/README.md) を使います。`sim_shim.h`、`Arduino.h`、`FS.h` は step8_mms と共有しているので、変えたら両方をビルドし直して確かめます。

## 仕組み

- `sim_shim.h` を `-include` で各 `.cpp` の先頭に読ませます。シムが `PICO_COMMON_H_` を先に定義するので、実機の `pico_common.h` は無効になります。Wi-Fi と SPIFFS 以外のヘッダは実機のものを使います。
- `Arduino.h` と `FS.h` は PC 用に最小限だけ用意した代わりのファイルです。
- `sim_harness.cpp` で、`RUN` の動作関数を「真の位置（mm）と向きを動かすだけ」の関数に置き換えます。
  - `straight`、`accelerate`、`decelerate`、`oneStep`、`oneStepDynamic`、`startAccelerate`: 指定の距離だけ前進します。
  - `rotate`: その場で回ります。区画の中心にいなければ失敗です。
  - `slalomCell`: 半区画進み、90°回り、さらに半区画進みます。正味の位置は実機と同じです。
  - `uTurn`: 90°回って後ろの壁に当てる動作を 2 回行います。当てる先に壁がなければ失敗です。
- 壁センサーの値は真の位置から 45mm 先の区画の壁から作ります。区画の境目付近では入ろうとしている区画の壁を、中心では今いる区画の壁を見ます。
- `/map.txt` の代わりに、メモリ上の 16×16 バイトの領域へ `mapWrite`/`mapCopy` します。

## ビルドと実行

リポジトリの直下で実行します。g++ は `C:\mingw64\bin` にあります。

```bash
S=srdc_8_micromouse
g++ -O2 -std=gnu++17 -w -include tools/step8_sim/sim_shim.h -I tools/step8_sim -I $S \
  tools/step8_sim/sim_harness.cpp $S/map_manager.cpp $S/search.cpp $S/search_dynamic.cpp \
  $S/fast.cpp $S/misc.cpp -o build/step8_sim.exe

build/step8_sim.exe 2000 0.35                  # 4x4（parameter.h の初期値）、壁の密度 0.35、2000 個
build/step8_sim.exe 1000 0.35 16 -g 7 7 8 8    # 16x16、ゴールは中央の 4 区画
build/step8_sim.exe 1000 0.35 16 -g 7 7 8 8 -i 633 -v   # 633 番の迷路だけを、迷路の図と動作ログ付きで実行
```

引数は `[迷路の数] [壁の密度] [迷路の一辺] [-g x y x2 y2] [-seed n] [-i 番号] [-v]` です。迷路は種と番号から決まるので、`-i` で同じ迷路を再現できます。

各迷路で、探索モード 2/3 をそれぞれ実行します。探索が成功したら、その地図を使って最短モード 4/5 を実行します（表の `4 after 3` は、モード 3 の地図でのモード 4 です）。

## 判定

| 項目 | 内容 |
| --- | --- |
| `ok` | 失敗がなく、ゴールの区画に入り、スタート区画の中心に北向きで戻り、`g_map.mypos` が真の位置と一致した |
| `optimal` | 最初にゴールへ入るまでの区画数が、正解の迷路での最短と同じ（探索で調べていない区画が残ると、最短モードでも遠回りになることがある。また最短モードは区画数ではなく走行時間が最小の経路を選ぶので、区画数では最短にならないことがある） |
| `collision` | 壁のある境目を通った |
| `turn off-center` | 区画の中心でない所で回った（距離の帳尻が合っていない） |
| `back into no wall` | `uTurn()` やスタート時の壁合わせで、当てる先に壁がない |
| `unreachable` | `nextDirGet()` が到達不能と判定した、または `fastPathMake()` が経路を作れなかった |
| `call limit` | `RUN` の呼び出しが多すぎる（無限ループの疑い） |

## 扱わないこと

- 壁は常に正しく読める前提です。センサーの雑音や誤判定は再現しません。
- `oneStepDynamic()` の前壁センサーによる早めの停止、壁制御、スラロームの軌跡、速度と時間は扱いません。
- 左手法（モード 1）はスイッチで止める前提なので対象外です。

## 結果

次のすべてで、全モードが `ok` になります（失敗 0 件）。

| 迷路 | ゴール | 壁の密度 | 迷路の数 | 区画数で最短になった割合（モード 4／5） |
| --- | --- | --- | --- | --- |
| 4×4 | (3,3) | 0.25／0.35／0.45 | 各 2000 | 100%／100% |
| 4×4 | (2,2)-(3,3) | 0.35 | 2000 | 約 94%／約 99% |
| 8×8 | (7,7) | 0.35 | 2000 | 約 91%／約 94% |
| 16×16 | (7,7)-(8,8) | 0.35 | 1000 | 約 70%／約 76% |

区画数で最短にならない理由は 2 つあります。

- 探索は行きと帰りの経路の周りしか調べないので、知っている壁だけで作る経路が遠回りになります。最短走行の復路も探索で戻るので、走るたびに未知の区画が埋まっていきます
- 最短モードは走行時間が最小の経路を選ぶので（[設計メモ §11](../../srdc_8_micromouse/DESIGN_NOTES.md)）、区画数が多くても旋回の少ない経路を選ぶことがあります。旋回の重いモード 4 の方が割合が低くなります
