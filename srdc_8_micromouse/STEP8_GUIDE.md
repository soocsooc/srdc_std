# STEP8 動作まとめ

`srdc_8_micromouse` は、SRDC2026 標準機体で迷路を探索し、最短経路で走るためのスケッチです。この文書は使い方と各機能の動作をまとめたものです。設計の理由は [DESIGN_NOTES.md](DESIGN_NOTES.md) にあります。

---

## 1. 概要とファイル構成

STEP1〜7 は LED・スイッチ・ブザー・センサ・モータ・壁の P 制御を 1 つずつ動かすサンプルです。STEP8 はそれらを組み合わせた、迷路を走破するためのアプリケーションです。

| ファイル | 役割 |
| --- | --- |
| `srdc_8_micromouse.ino` | `setup()`／`loop()`。初期化とモード選択 |
| `device.cpp`／`device.h` | ピン定義、タイマー、センサタスク、モータのパルス生成、LED・ブザー・スイッチ・センサ・電池電圧 |
| `run.cpp`／`run.h` | 走行制御（1kHz の速度更新、壁の P 制御、加減速、超信地旋回、スラローム旋回） |
| `run_dynamic.cpp` | 前壁で区画境界を判定する直進 `oneStepDynamic()`、スタート位置合わせ |
| `sensor.cpp`／`sensor.h` | 壁センサの平滑化、壁の判定、P 制御用の誤差、低電圧の警告 |
| `search.cpp`／`search.h` | 左手法（モード 1） |
| `search_dynamic.cpp` | 前壁で区画境界を判定する足立法（モード 2・3）、後ろへの回転 `turnBack()` |
| `fast.cpp`／`fast.h` | 最短走行とそのスラローム版 |
| `map_manager.cpp`／`map_manager.h` | 壁情報、歩数マップ、次に進む方向の決定 |
| `Flash.cpp`／`flash.h` | 迷路情報とパラメータの保存（SPIFFS）、USB シリアルからのパラメータ設定 |
| `misc.cpp`／`misc.h` | スイッチの操作音、ゴールアピール、走行モードの実行 |
| `adjust.cpp`／`adjust.h` | 調整メニュー |
| `webserver.cpp`／`web.h` | Wi-Fi のアクセスポイントと、パラメータ調整用の Web ページ |
| `parameter.h` | パラメータの初期値と定数 |
| `pico_common.h` | すべての `.cpp` が読む共通ヘッダ。ヘッダの読み込み順をここで管理する |

各 `.cpp` は独立してコンパイルされます（`.ino` の連結ではありません）。

## 2. ハードウェア

ESP32-DevKitC-32E（無印 ESP32）とモータドライバ EIC4311（SLA7078 互換）を使います。ピンは回路図 V5（11/3 版）に合わせて `device.h` で定義しています。

| 機能 | ピン | 備考 |
| --- | --- | --- |
| LED0〜3 | 5, 13, 16, 15 | 回路図の L_1〜L_4。HIGH で点灯し、モード番号を 2 進数で表示する |
| SW1 | 33 | 内部プルアップを使う |
| SW2 | 35 | 入力専用ピンで内部プルアップがない。プルアップしていないなら `USE_SW2` を 0 にする（下記） |
| センサ LED（前・右・左） | 14, 4, 27 | HIGH で点灯。前は 1 個 |
| 受光素子（前・右・左） | 36, 39, 34 | ADC1。前・右・左の割り当ては実機で確認する |
| 電池電圧 | 32 | 51kΩ と 10kΩ の分圧 |
| ブザー | 23 | |
| MOTOR_EN | 17 | **HIGH で有効**、LOW でドライバが SLEEP |
| CLOCK（右・左） | 19, 18 | 1 パルスで 1 ステップ |
| CW/CCW（右・左） | 22, 21 | 前進時の出力は `CW_R_FORWARD`／`CW_L_FORWARD` |

- モータの電流は基板のトリマ（R26）で合わせます
- 電池は LiPo 3 セルを想定しています。残量 LED はありません。電圧が 10.0V（`BATT_MIN`）を 200ms 続けて下回ると、ブザーを鳴らして LED を消します
- GY-521（ジャイロ）は I2C（SDA 25、SCL 26）につながっていますが、このスケッチでは使いません
- 受光素子の信号線には、1MΩ（R7〜R9）で 3.3V へのプルアップが入っています。受光側は 5.1kΩ で GND に落ちているので、計算上は約 17mV のオフセットが乗り、光がなくても値は 0 になりません
- SW2 をプルアップしていないなら、`device.h` の `USE_SW2` を 0 にします。SW2 を読まず、SW1 の短押しが「次」、長押し（`SW_LONG_PRESS_MS`、1 秒以上）が「決定」になります。長押しになった時点で短い音が鳴るので、そこで離します

## 3. 起動と操作

### 起動

`setup()` は次の順に初期化します。

1. `deviceInit()`：GPIO、タイマー（制御 1kHz、左右のパルス生成）、センサタスク、シリアル（115200bps）を初期化します
2. `flashBegin()`：SPIFFS をマウントします。**SW2（`USE_SW2` が 0 なら SW1 の長押し）を押しながら起動すると `flashInit()`** で、保存されたパラメータを `parameter.h` の初期値に戻します。迷路情報は消えないので、消すときは走行モード 6 を使います
3. `paramRead()`：`/parameters.txt` からパラメータを読み込みます（§9）
4. `mapCopy()`：`/map.txt` から前回の迷路情報を読み込みます
5. 起動音を鳴らし、モータを無効にして、モード 1 の選択から始めます

### モード選択

`loop()` は次の操作を受け付けます。

| 操作 | 動作 |
| --- | --- |
| 次（SW1） | モード番号を 1 つ進める（7 の次は 1）。高い音が鳴る |
| 決定（SW2） | 選んでいるモードを実行する。確認音が鳴る |

- 選んでいるモード番号は LED に 2 進数で表示されます（LED0 が 1 の位）
- スイッチは離されるまで待ってから 1 回押したと判定します
- 待機中は USB シリアルからパラメータを設定できます（§9）

## 4. 走行モード

どのモードも実行前にモータを有効にして 1 秒待ち、終わったらモード番号の LED 表示に戻してモータを無効にします（[設計メモ §13](DESIGN_NOTES.md)）。走行モード 1〜5 は走り出す前に後ろ壁に当てて区画の中心に合わせます（[設計メモ §6](DESIGN_NOTES.md)）。そのため、スタート区画の後ろに壁がある状態で始めます。

| 番号 | 関数 | 動作 |
| --- | --- | --- |
| 1 | `SEARCH::lefthandGetWall()` | 左手法で走りながら壁を記録する。ゴールに着くかスイッチを押すと止まり、迷路情報を保存 |
| 2 | `SEARCH::adachiDynamic()` | 足立法でゴールまで探索 → 180° 回転 → ゴールアピール → スタートへ探索しながら戻る → 迷路情報を保存。前壁が見えたら区画境界とみなす `oneStepDynamic()` で進む（[設計メモ §4](DESIGN_NOTES.md)）。巡航速度は `stoppableSpeed(HALF_SECTION)` |
| 3 | `SEARCH::adachiSlalomDynamic()` | モード 2 の 90° 旋回を `slalomCell()` にしたもの。到達判定と側壁にモード 3 専用のしきい値を使う（[設計メモ §4・§5](DESIGN_NOTES.md)） |
| 4 | `FAST::run()` | 保存した迷路情報で走行時間が最短の経路をゴールへ走る。復路はモード 2 の走り方で探索しながら戻り、迷路情報を保存 |
| 5 | `FAST::runSlalom()` | モード 4 の 90° 旋回を `slalomCell()` にしたもの。復路はモード 3 の走り方で探索 |
| 6 | `mapErase()` | Flash の迷路情報を消去する。モータは動かさない。完了すると確認音が鳴る |
| 7 | `ADJUST::menu()` | モータを無効にして調整メニューへ移る（§5） |

### 左手法（モード 1）の流れ

自己位置を (0,0)・北向きにしてから、左手法で進みます。区画境界ごとに `wallSet()` で壁を記録し、左・前・右の順に空いている方向へ進みます。行き止まりでは 180° 回転します。ゴールの区画に入るかスイッチを押すと半区画で止まり、`mapWrite()` で迷路情報を保存します。左手法なので、迷路の形によってはゴールに着かないことがあります。

### 探索（モード 2・3）の流れ

```text
positionInit()                     // 自己位置を (0,0)・北向きにする
探索関数(ゴール)                    // ゴールまで探索
rotate(right, 2)                   // 180° 回転
goalAppeal()                       // LED の演出と迷路情報の保存
探索関数(0, 0)                      // スタートへ探索しながら戻る
rotate(right, 2)
mapWrite()                         // 迷路情報を保存
```

探索関数の中では区画境界ごとに `wallSet()` で壁を記録し、`nextDirGet()` が返す方向へ進みます。

- 前：`oneStepDynamic()` で、前壁が見えるか 1 区画進むまで走る
- 右・左：モード 2 は半区画減速 → `rotate()` → 半区画加速、モード 3 は `slalomCell()`
- 後ろ：半区画減速 → 180° 回転 → 半区画加速。回転はモード 2 が `rotate()`、モード 3 が `turnBack()`

### 最短走行（モード 4・5）の流れ

```text
mapCopy()                          // Flash から迷路情報を読む
positionInit()
最短走行関数(ゴール)
rotate(right, 2)
goalAppeal()
探索関数(0, 0)                      // モード 4 は adachiDynamic()、モード 5 は adachiSlalomDynamic()
rotate(right, 2)
mapWrite()
```

壁がないと確定した辺だけを通り、走行時間が最小になる経路をダイクストラ法で作ります。重みは直進・旋回の所要時間で、走行パラメータから計算するので、モード 4 とモード 5 では選ぶ経路が違うことがあります。直進区間はまとめて `max_speed` まで加速します。曲がり角とゴールの前後は、半区画で止まり切れる速度に抑えます。走り出すときに Serial へ経路と推定時間を出します。詳しくは [設計メモ §11](DESIGN_NOTES.md) を参照してください。

### ゴールに到達できないとき

壁情報がおかしくなりゴールへ到達できないと判定すると、モータを止めて LED を交互に点滅させます。スイッチを押すとモード選択に戻ります。このとき迷路情報は保存しません（[設計メモ §8](DESIGN_NOTES.md)）。

### ゴールアピール

モータを無効にして迷路情報を保存し、LED を左右に流すアニメーションを 10 回（だんだん速く）してから、モータを有効に戻します。

## 5. 調整メニュー

走行モード 7 で入ります。LED3 が点滅して、走行モードの選択と区別されます。「次」で番号を進め（11 の次は 1）、「決定」で実行します。11 を実行すると走行モードの選択に戻ります。待機中は USB シリアルからパラメータを設定できます。

| 番号 | 関数 | 動作 |
| --- | --- | --- |
| 1 | `webServerSetup()` | Web サーバを起動する（§10）。ピッ、ピッと鳴ってから起動 |
| 2 | `rotationCheck()` | 右 90° 旋回を 8 回（720°）する。トレッド幅の調整用 |
| 3 | `circuitCheck()` | 4×4 の最外周を「2 区画直進 → `slalomCell()`」で周回する。スイッチを押すと角を曲がった後に止まる。LED の点灯数は旋回の出口のずれ（[設計メモ §3](DESIGN_NOTES.md)） |
| 4 | `straightToWallCheck()` | 前壁が見えるまで直進し、区画の中心で止まる。壁の P 制御のゲイン調整用 |
| 5 | `straightCheck(3)` | 3 区画直進する。タイヤ径の調整用 |
| 6 | `adcView()` | センサ値・電池電圧・棄却したサンプル数をシリアルに表示し続ける。いずれかのスイッチで戻る |
| 7 | `slalomSequenceCheck()` | 右→左（S 字）→ 1 区画直進 → 右→右（U 字）を一続きに走る |
| 8 | `straightSensorDiag(2.2)` | 壁へ向けて直進し、距離と前センサの値をシリアルに出す。モード 2・3 の到達しきい値を決める |
| 9 | `slalomTurnCheck(right)` | 2 区画直進して区画境界で 1 回曲がり、次の区画の中心で止まる |
| 10 | `frontThresholdCalib()` | 前センサの壁ありなしのしきい値を測って保存する（[設計メモ §7](DESIGN_NOTES.md)） |
| 11 | ― | 走行モードの選択に戻る |

- 調整モード 3・4・5・7・8・9 は、走り出す前に後ろ壁に当てて区画の中心に合わせます。開始区画の後ろに壁を置いてください
- 調整モード 4：`startAccelerate(HALF_SECTION)` の後、`oneStepDynamic()` で前壁が見えるまで直進します。前センサの値が `th_approach` を超えたところを区画境界とみなし、`decelerate(HALF_SECTION)` で区画の中心に止まります。速度はモード 2 と同じ `stoppableSpeed(HALF_SECTION)` です。走行中は `len/f` をシリアルに出し、スイッチで止められます。前壁がないときのため、距離の上限を 16 区画にしています
- 調整モード 8：センサでは止まらないようにして、`2.2` 区画まで走ります。この距離はスタート位置（後ろ壁に当てた機体の先端）から壁まで 580mm の環境で、壁の半区画手前に余裕をもって止まるように決めた値です。壁の距離を変えたら `adjust.cpp` の case 8 も変えます。走行中にスイッチを押すとすぐに止まり、その後の減速もしません
- 調整モード 10：区画中央に置き、1 区画先（次の区画の奥）に壁を置いて、LED `0b0110` の状態で「決定」を押します。確認音の後、壁を外して LED `0b1001` の状態で「決定」を押します。「次」を押すと中止し、何も保存しません

## 6. 走行制御

走行制御は `run.cpp` にあります。

### 速度の更新

`RUN::interrupt()` が 1kHz で次の処理をします。

1. `speed += accel` を毎周期足し、`upper_speed_limit`／`lower_speed_limit` の範囲に収めます
2. 壁の P 制御が有効（`con_wall.enable`）なとき
   - 左右両方の壁が制御範囲内なら `error = sen_r.error − sen_l.error`、片方だけなら `error = 2 × (sen_r.error − sen_l.error)`
   - `control = 0.001 × speed × kp × error`（速度に比例させ、速度によらず同じように収束させる）
   - 右の目標速度 = `speed + control`、左 = `speed − control`
   - 旋回中は無効にします。旋回中に壁センサが反応すると、狙った角度まで回れないためです
3. スラローム中（`turn_enable`）は、外輪と内輪の速度を `turn_f` から計算します（[設計メモ §3](DESIGN_NOTES.md)）
4. どちらでもなければ、左右とも `speed` です。最後に左右とも `MIN_SPEED`（30mm/s）以上にします

### 主な走行関数

| 関数 | 動作 |
| --- | --- |
| `accelerate(len, finish)` | `MIN_SPEED` から `finish` まで加速して `len` 進み、等速のまま終える |
| `straight(len, init, max, finish)` | 加速し、残りの距離が制動距離を切ったら減速する。`finish` が `MIN_SPEED` なら止まり、それ以外は等速のまま終える。壁の P 制御あり |
| `oneStep(len, init)` | 加減速なしで `len` 進む |
| `decelerate(len, init)` | 減速して止まる |
| `oneStepDynamic(max_len, init, th, debug_log)` | 等速で進み、前センサの値が `th` を超えるか `max_len` に達したら、等速のまま終える（[設計メモ §4](DESIGN_NOTES.md)） |
| `rotate(dir, times)` | その場で 90° × `times` 回る。止まった状態から呼び、止まって終わる |
| `slalom(dir, angle)`／`slalomCell(dir)` | 止まらずに曲がる（[設計メモ §3](DESIGN_NOTES.md)） |
| `uTurn(dir)` | 90° 旋回 → バック → 前進を 2 回して、壁に当てながら 180° 回る（[設計メモ §6](DESIGN_NOTES.md)） |
| `startAccelerate(len, finish, align)` | 後ろ壁に当てて区画の中心に合わせてから加速する（[設計メモ §6](DESIGN_NOTES.md)） |
| `stoppableSpeed(len)` | `len` で止まり切れる速度（[設計メモ §11](DESIGN_NOTES.md)） |
| `stay(speed)` | 等速のまま、パルスカウンタをクリアする。迷路の判断をしている間もタイヤを止めずに転がし続けるため |
| `stop()` | パルスの出力を止め、300ms 待つ |

- 距離はパルス数で測ります。`pulse = tire_diameter × π / PULSE_PER_REV`（[設計メモ §1](DESIGN_NOTES.md)）
- `straight()`・`oneStep()`・`decelerate()` は開始時にパルスカウンタをクリアしません（[設計メモ §2](DESIGN_NOTES.md)）

## 7. センサ処理

センサの処理は `sensor.cpp` と `device.cpp` にあります。

### 読み取りの流れ

壁センサは、core1 に固定した FreeRTOS タスク `sensorTask`（優先度 20）が 1ms ごとに読みます。1 周期で `sensorInterrupt()` を 4 回呼び、次の順に処理します。

| `cnt` | 処理 |
| --- | --- |
| 0 | 電池電圧の測定と低電圧の警告（センサ LED は使わない） |
| 1 | 前センサ（`sen_f`） |
| 2 | 右センサ（`sen_r`） |
| 3 | 左センサ（`sen_l`） |

- 前センサ：値が `th_wall` を超えれば前壁あり（[設計メモ §7](DESIGN_NOTES.md)）
- 横センサ：値が `th_wall` を超えれば壁ありとして P 制御にも使い、`error = value − ref` とします

### センサ LED の点灯と読み取り

`sledRead()` はセンサ LED を点けてから `SLED_SETTLE_US`（32µs）待って AD 変換し、LED を消します。受光の出力は LED を点けた直後に一瞬出る減衰波形なので、読むタイミングが揺れると値も揺れます。傾きの緩い部分で読むよう、待ち時間を決めています。

点灯から AD 変換が終わるまでの時間を測り、`SLED_WINDOW_MAX_US`（200µs）を超えたら、そのサンプルを捨てて前回の値を使います（`SENSOR_SAMPLE_BAD`）。捨てた数は調整モード 6 の `reject` に表示します。

### 平滑化

1 回の点灯で 1 回だけ読み、3 サンプルのメディアン（単発のスパイクを除く）→ IIR フィルタ（`value = (value × 3 + in) / 4`、時定数 約 3ms）の順に通します。

### Wi-Fi との関係

センサを Wi-Fi・AsyncTCP（core0）と別のコアのタスクで読むのは、Wi-Fi の割り込みでセンサ LED の点灯時間が延び、値が下がってばらつくのを防ぐためです。タスクが待機から起きた直後は揺れが大きいので、その回（`cnt` 0）にはセンサ LED を使わない電池電圧の処理を置いています。

Wi-Fi の送信で電源が一瞬下がると、ブラウンアウト（`E BOD`）や低電圧ブザーの誤作動が起きることがあります。そのため Web サーバの送信出力を `WEB_WIFI_TX_POWER`（8.5dBm）に下げ、低電圧ブザーは 200ms 続けて下がったときだけ鳴らします。それでも起きるときは、USB ではなく充電済みの電池で動かしてください。

しきい値などの校正は Wi-Fi を使わない調整モード 6 の値を基準にします。

## 8. 迷路管理

壁情報、歩数マップ、最短走行の経路は `map_manager.cpp` で扱います。

- 迷路の大きさは `maze_x`／`maze_y`（2〜16、初期値は 4×4）です。Web UI の `MAZE SIZE` で変えられます（[設計メモ §9](DESIGN_NOTES.md)）
- 壁は 1 区画を 1 バイト（北・東・南・西 各 2 ビット）で持ちます。値は `NOWALL`（0）／`WALL`（1）／`_UNKNOWN`（2）です
- 初期状態は、全区画が未知、外周が壁、スタート区画の東が壁で北が壁なしです
- `wallSet()`：自己位置の向きに応じて、今いる区画と隣の区画の壁を同時に書き込みます
- `searchMapMake()`（探索用）：壁でない辺（未知も通れるとみなす）で歩数マップを作ります
- `fastPathMake()`／`fastPathNext()`（最短走行用）：壁がないと確定した辺だけを通り、走行時間が最小の経路をダイクストラ法で作って、区画ごとに次の方向を返します（[設計メモ §11](DESIGN_NOTES.md)）
- `nextDirGet()`（探索用）：4 方向のうち歩数が最小の方向を選びます。同点なら、直進＋2、横＋1、後ろ＋0、未知の壁がある区画＋4 の優先度で選びます（未探索の方向を優先するのが足立法の探索の性質）
- ゴールは長方形の対角 2 座標で指定します（[設計メモ §9](DESIGN_NOTES.md)）

迷路管理と探索・最短走行は、PC 上でも確かめられます。[tools/step8_sim](../tools/step8_sim/README.md) はランダムな迷路でまとめて判定します。[tools/step8_mms](../tools/step8_mms/README.md) はシミュレーター mms の上で走らせ、覚えた壁と、方向を決めるたびに作り直される歩数マップを画面に表示します。

## 9. Flash 保存とパラメータ

保存と読み込みは `Flash.cpp` が行います。

### 保存するファイル

| ファイル | 内容 |
| --- | --- |
| `/map.txt` | 迷路情報（16×16 バイト）。[設計メモ §10](DESIGN_NOTES.md) |
| `/parameters.txt` | パラメータ（「キー 値」の行）。Web・USB シリアルで変えた値はここに保存される |

- パラメータは `param_table` で一元管理しています。読み込み時の扱いや、速度・加速度の妥当性チェックは [設計メモ §12](DESIGN_NOTES.md) を参照してください
- 保存した値は電源を切っても残り、書き込み直しても消えません。**理由がわからない不調が出たら、まず「決定」を押しながら起動して初期値に戻す**と切り分けが早くなります
- Flash へ書き込む間は、制御・センサ・パルス生成の割り込みを止めます。書き込むのはモータを止めているときだけです

### USB シリアルからの設定

待機中（モード選択と調整メニュー）は、シリアルモニタ（115200bps）から次のコマンドを受け付けます。走行中は受け付けません。行末は CR・LF のどちらでもよく、1 行は 64 文字までです。

| コマンド | 動作 |
| --- | --- |
| `list` | 全パラメータを「キー 値」で表示する |
| `list_r`／`list_a` | 走行モード／調整モードの一覧を表示する |
| `set <キー> <値>` | 値を設定して、すぐ反映・保存する。設定後の値を表示してブザーを鳴らす。範囲外なら初期値に戻ったことが表示でわかる |

## 10. Web サーバ

`webserver.cpp` の Web サーバは調整モード 1 で起動します。

- アクセスポイントの SSID は `SRDC_STD`、パスワードは `12345678` です。ブラウザで `http://192.168.4.1` を開きます
- 電池電圧とセンサ値（`SIDE VALUE`／`FRONT VALUE`）を表示します。`FRONT VALUE` は前センサの値です
- パラメータを変えて Enter か Save を押すと、すぐ反映して Flash に保存します。入力欄の名前は `/parameters.txt` のキーと同じです
  - `Sensor Parameter`：`Sensor ratio` と、REF・しきい値のベース値。括弧内に倍率を掛けた実際の値を表示します。`FRONT measured` 行は調整モード 10 の測定値です（表示のみ）
  - `FRONT Approach Threshold`／`FRONT Approach Threshold(Slalom)`：モード 2・3 の到達しきい値（前センサの値と比べる）
  - `SIDE Threshold(Slalom)`：モード 3 の側壁しきい値
  - `Slalom Parameter`：`Slalom speed`・`Slalom inner ratio`・`Slalom outer gain`・`Slalom ramp len` と、計算した `Slalom offset`
  - `GOAL Parameter`：迷路の大きさ（`MAZE SIZE`）とゴールの対角 2 座標（`AXIS`／`AXIS2`）。迷路の大きさを変えて保存すると迷路情報を消去します
- 迷路図（`Maze Map`）、走行モード・調整モードの一覧、各パラメータの効果の目安も表示します
- センサ値の表示には、リクエストごとに直近 5 個のメディアンを使います。Wi-Fi の影響で残る大きめの外れ値を表示から除くためで、制御に使う値は変えていません
- ルータにつなぐ場合は `AP_MODE` をコメントアウトして SSID とパスワードを書き換え、割り当てられた IP アドレスをシリアルモニタで確認します

## 11. 初めて走らせるまでの調整

標準機体のパラメータの初期値は未校正の仮の値です。次の順に合わせます。

1. 配線と向きの確認（STEP1〜6）
   - STEP2 で両方のスイッチが反応することを確かめます（SW2 をプルアップしていないなら `USE_SW2` を 0 にします）
   - STEP1 で LED が L_1〜L_4 の順に並んでいることを確かめます
   - STEP4 でセンサ値を表示し、前・右・左の受光素子の割り当て（`AD_F`／`AD_R`／`AD_L`）を確かめます
   - STEP5 で前進するか確かめます。逆に回るモータは `CW_R_FORWARD`／`CW_L_FORWARD` を反転します
   - 1 回転あたりのパルス数（`PULSE_PER_REV`）を、1 回転させて確かめます
   - モータの電流を基板のトリマ R26 で合わせます
2. センサの物理調整：横センサは壁に対して 15〜45° 外向き、前センサは 1〜5° 外向きにし、光が壁の高さを越えないようにします
3. センサの基準値・しきい値（調整モード 1 の Web か、調整モード 6）
   - `SIDE REF`：区画中央に置いたときの横センサの値
   - `SIDE Threshold`：反対側の壁に寄せたときの値。壁のありなしで十分な差が必要です
   - `FRONT Threshold`：調整モード 10 で測ります
4. P ゲイン（調整モード 4）：壁際に置き、3〜4 区画で中央に寄るよう `Gain` を合わせます
5. タイヤ径（調整モード 5）：`新しい径 = 今の径 × 実際の距離 / 目標の距離` で直し、誤差 1mm 以下になるまで繰り返します
6. トレッド幅（調整モード 2）：`新しい幅 = 目標の角度 / 実際の角度 × 今の幅` で直します
7. スラローム（調整モード 3・9・7）：旋回が区画に収まり、つなぎで脱調しないよう、`Slalom inner ratio`・`Slalom ramp len`・`Slalom outer gain` を合わせます。`Slalom offset` が 90mm を超えないようにします
8. モード 2・3 の到達しきい値（調整モード 8）：距離と前センサの値を測り、区画境界で止まる値を `FRONT Approach Threshold` に入れます
9. ゴール座標：Web の `AXIS`／`AXIS2` で指定します。初期値は練習用の 4×4 で (3,3)-(3,3)、大会の 16×16 なら中央 4 区画の (7,7)-(8,8) です。新しい迷路を走る前に、モード 6 で迷路情報を消します

### 各パラメータの効果の目安

Web ページの最下部にも同じ内容を表示しています。

| パラメータ | 大きくすると | 小さくすると |
| --- | --- | --- |
| `Gain`（`con_kp`） | 中央へ速く寄るが、大きすぎると蛇行・振動・脱調する | 壁に寄ったままなかなか戻らない |
| `SIDE REF` | ずれていると、ゲインを合わせても中央からずれた位置に落ち着く | 同左 |
| `SIDE/FRONT Threshold` | 壁があるのに「なし」と判定する | 壁がないのに「あり」と判定する |
| `TIRE_DIAMETER` | 目標の手前で止まる | 目標を行き過ぎる |
| `TREAD_WIDTH` | 曲がり不足 | 曲がりすぎ |
| `Search accel` | 最高速に早く届くが、急すぎるとスリップ・脱調する。曲がり角での速度の上限も上がる | 滑らかだが、短い区間では速度が出ない |
| `Turn accel` | 早く回れるが、振られやすい | 確実だが時間がかかる |
| `Slalom inner ratio` | 大回りになり、張り出しが大きくなる | 小回りになる。0 でほぼ内輪を軸に回る |
| `Slalom ramp len` | 滑らかに曲がり始めるが、張り出しが大きくなる | 張り出しは小さいが、急に曲がり始めて姿勢が乱れやすい |
| `Slalom outer gain` | 同じ形のまま早く曲がり終わるが、外輪がスリップしやすい | 外輪は増速しない（0） |
| `Slalom speed` | 早く曲がり終わるが、遠心力でスリップしやすい（軌跡は変わらない） | 確実だが時間がかかる |
| `Sensor ratio` | REF としきい値がまとめて大きくなる | まとめて小さくなる |
| `Search speed` | 探索は速いが、センサや P 制御が追いつかず衝突しやすい | 安定するが時間がかかる |
| `max speed` | 記録は縮むが、加減速の余裕が減る | 安全だが記録が伸びない |
